# Сборка ролика

Полный канон производства — `docs/METHOD.md`. **Прочитай его целиком перед первой
сценой.** Затем `style/IDIOM.md` и `style/tokens.ts` — визуальный язык текущего
стиля. Порядок шагов конвейера — `docs/PIPELINE.md`.

Ничего из этого не пересказывай человеку. Он ждёт ролик, а не отчёт о чтении.

## Прежде чем начать

`"configured": false` — предложи настройку и свой стиль одной фразой. Человек
отказался, промолчал или просто прислал видео — собирай на значениях по умолчанию.

Ролик собирается в отдельном разговоре. Если это уже второй ролик за беседу —
предложи открыть новый: так быстрее и чище.

## 1. Приём

Заведи проект. Папку создаёт скрипт, человека не проси ничего складывать:

```
npm run intake -- --name "короткое имя" /путь/к/файлу
```

Что пришло, то и передавай: озвучку, видео с камеры, текст. Пришла одна тема —
сначала сценарий, утверждение у человека, и только потом дальше.

## 2. Звук и тайминги

Готовая озвучка или видео — распознавание:

```
npm run transcribe -- --project ID
```

Текст сценария и подключённый ElevenLabs — синтез, распознавание не нужно, метки
приходят вместе со звуком:

```
node scripts/tts.mjs --project ID --text-file projects/ID/source/script.md
```

Дальше чистка и разметка:

```
npm run cleanup -- --project ID
npm run blocks -- --project ID
```

**Прочитай `work/blocks.md` и поправь разбивку по смыслу.** Скрипт режет по паузам
— это черновик. Границы должны совпадать с границами мыслей, а не с тишиной. Если
правишь границы, правь `work/blocks.json` и пересобирай каркас: длительности
пересчитаются, и сумма снова сойдётся с дорожкой.

Чистка по умолчанию мягкая — так и задумано. Ужесточай только по просьбе:
`--min-silence 0.4`, `--threshold -30`.

## 2б. Кто в кадре — если прислали видео с камеры

Шаг только для видео. Прислали звук или текст — пропусти, там графика везде.

**Сначала спроси человека одной фразой:** «Вас в кадре показываем или видео
только ради голоса?» Это единственное, чего нельзя узнать самому, и ответ меняет
весь ролик.

- **«только голос»** — сними пометку `camera` со всех блоков в `work/blocks.json`.
  Изображение не появится нигде, останется звук. Ролик будет обычным
  анимированным.
- **«показываем»** — разметь сам, блок за блоком, и покажи человеку результат
  списком, а не спрашивай про каждый.

Как размечать. Камере отдавай то, что держится на человеке: зацепку, личное
суждение, обращение к зрителю, призыв в конце. Графике — то, что на лице не
читается: числа, перечисления, сравнения, схемы, блоки со скринами. Чередуй:
подряд идущие пять камерных блоков — это разговорное видео, а не ролик.

Правится поле `camera` в `work/blocks.json`, дальше каркас. Сцены создадутся
только для графических блоков — камерные их не требуют, и это экономит половину
работы.

Полное правило — `docs/METHOD.md`, раздел 3.4а. Главное оттуда: графика **не
кладётся поверх** говорящего лица. Либо человек, либо кадр графики на своём фоне.

## 2а. Скрины, если они нужны

Решается здесь, между разметкой и сценами: раньше неизвестно, что доказывать,
позже сцена уже написана под картинку, которой может не быть.

Скрин ставится там, где блок утверждает факт, в котором зритель усомнится: цифра,
чужой интерфейс, цена, дата. Три-четыре на ролик, не в зацепке. Подробности — в
разделе про скрины в `docs/METHOD.md`.

Человек прислал снимки сам:

```
npm run shots -- --project ID --import /путь/скрин.png
```

Нужна съёмка сайта, а функция выключена — не включай молча и не отказывай глухо.
Скажи три вещи: это отдельная функция и сейчас она выключена; почитать о ней —
мануал, раздел 2.5 (он же `docs/GUIDE.md`); включить можно сказав «включи
съёмку сайтов». Согласился
— поставь `shots.web: true` в `config/project.json` и продолжай. Не согласился —
обойдись его снимками или графикой, ролик от этого не встанет.

Функция включена — собери `projects/ID/shots.json` и сними:

```
npm run shots -- --project ID --capture
```

В кадр снимок ставится только через `ScreenPlate` с наездом на нужный фрагмент.
Голый `Img` — неподвижная чужеродная вставка, то есть брак.

## 3. Каркас

```
npm run scaffold -- --project ID
```

Появляются файлы сцен-заглушек, описание ролика и запись в реестре. Обвязку руками
не пиши — её задача уже решена.

Заглушки создаются только для графических блоков. Если после каркаса передумали и
блок надо перевести из камеры в графику или обратно — правь `work/blocks.json` и
пересобирай каркас с `--force`, а не дописывай `reel.tsx` руками.

## 3а. Субтитры — включаются сами

По умолчанию субтитры кинетические. После каркаса в `reel.tsx` рядом с
`captions` пишется `captionPlan` — строка на фразу, слова в порядке и числе
`captions.json`. Разметка — в шапке `core/kinetic.ts`. Фраза целиком стоит
сверху или снизу; наверх — короткий вопрос, вывод и подобное. Зум — иногда,
по смыслу.

Ничего делать не нужно: каркас кладёт в проект слова чистой дорожки, а сборка
рисует субтитры поверх сцен. Разбивку на страницы система считает сама по темпу
речи и ширине кадра — вручную её не подбирай и человека о ней не спрашивай.

Настраиваются словами, а не вопросами вперёд. Что человек может попросить и что
менять в блоке `subtitles` файла `config/project.json`:

| Просьба | Поле |
|---|---|
| «сделай субтитры как у всех» / «в цветах моего стиля» | `look`: `white` или `brand` |
| «обычные субтитры», «как раньше» | `look: "white"` |
| «без зума», «камера пусть стоит» | `camera.zoom: false` |
| «подними повыше», «слишком низко» | `position` |
| «крупнее», «мельче» | `size` |
| «не надо подсвечивать слово» | `highlight` |
| «субтитры наложу сам в сервисе» | `mode: "external"` |
| «убери субтитры совсем» | `mode: "none"` |

После правки конфига нужен новый рендер. Файлы `.srt` система не делает — если
просят, скажи прямо: субтитры внутри ролика, отдельным файлом их нет.

Правило про текст в кадре свои субтитры не отменяют: подпись остаётся якорем
смысла, а не второй строкой субтитров.

Просят «пусть слова идут по одному» или «убери подсветку» — это `subtitles.chunk`
в `config/project.json`: `word` вместо `page`. Склейку коротких слов ядро делает
само, руками её трогать нечем.

## 4. Сцены — здесь настоящая работа

По одной сцене на графический блок; камерные блоки сцен не требуют. Для каждой:

1. Найди **метафору**: движение, которое БУДЕТ смыслом фразы, а не украшением
   рядом. Проверка — убери весь текст: мысль читается из одного движения? Нет —
   думай заново.
2. Собери её из примитивов `core/` и токенов стиля. Свои цвета не выдумывай:
   не хватает — спроси человека.
3. Заполни движением **всю** длину блока: растянутое действие, живое послесвечение
   или цепочка микро-событий. Живой фоновый слой сам по себе не считается.
4. Подпись — только там, где добавляет то, чего в движении нет: имя, число,
   адрес, слово вроде «твой». Сцена, понятная без слов, остаётся без слов; в
   первых секундах слово или число обычно окупается. Пересказывать речь нельзя:
   субтитры и так внизу.
4а. У вещей внутри кадра имена пишутся: файл `reel.tsx`, кнопка «собрать», модель
   Gemini. Серые полоски — только там, где текст и есть масса, которую читать не
   надо (абзац, код в фоне). Правило — `docs/METHOD.md`, раздел 5б.
5. Заголовки — только через `FitText`, он измеряет строку сам. Кегли на глаз не
   подбирай.

Готовую сцену из другого проекта бери только при точном совпадении смысла и всегда
с вариацией — ритм, число, ракурс. Никогда один в один. Механики под типовые
фразы и анатомия насыщенного кадра — `docs/SCENES.md`.

## 5. Рендер

**Перед первым рендером пройди все сцены по числам** и проверь замирание счётом:
последнее движение блока кончается не раньше чем за пять кадров до его конца,
промежутков длиннее двадцати кадров нет, длину держит предмет-герой, а не
галочка или стрелка. Правила — `docs/METHOD.md`, раздел 4.

```
npm run render -- --project ID
```

Проверки прогоняются сами. На замечания о замирании картинки реагируй по делу:
это почти всегда недоделанная сцена, а не ложная тревога.

Со своими субтитрами проверка на мёртвый кадр слепнет: подсветка слова меняет
картинку каждый кадр. Проверка честно об этом предупреждает — значит пролистай
готовый ролик глазами сам, а не полагайся на «всё чисто».

Рендер идёт минуты. Не отвлекай человека в процессе, покажи результат.

## 6. Отдача

Скажи, где лежит файл, и коротко — из скольких сцен собран ролик. Снимали на
камеру — скажи и то, сколько блоков осталось за человеком, а сколько ушло графике. Если проверка
что-то отметила, скажи об этом прямо, не заглаживая.

Называй **общую папку `OUT REELS` рядом с системой** — за роликами человек ходит
туда. Других копий ролика нет. Если перенести его в общую папку не удалось,
рендер скажет, где лежит файл, — назови это место.

Стиль ещё базовый (`name` в `style/tokens.ts` — «Нейтральный (по умолчанию)») —
одной фразой напомни, что ролик собран в базовом оформлении и свой стиль
подключается просьбой «поменяй стиль».

## Правки

Правки только что собранного ролика — в этом же разговоре. Меняй сцену, рендерь
заново. Длительности блоков не трогай: они посчитаны по голосу, и описание ролика
не даст их сдвинуть.
