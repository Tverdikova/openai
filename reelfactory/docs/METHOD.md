# Канон производства

Один файл — вся суть. Читается целиком перед сборкой или правкой любого ролика.
Правила разбросанные по нескольким документам всегда частично пропускаются, и это
сразу видно в результате: крупный текст, дублирующий субтитры, замершие кадры,
случайные цвета.

Здесь только то, что не зависит от стиля. Как выглядит конкретно ваш мир — в
`style/IDIOM.md`. Конкретные значения цвета и кегля — в `style/tokens.ts`, а не
здесь и не в голове.

Порядок разделов — порядок чтения.

## 1. Что мы вообще анимируем

Внизу кадра весь ролик идут субтитры — свои или чужие, это настройка, а не
разные методики. Значит текст речи и так на экране. Отсюда всё остальное:

- Наш кадр — не подпись к словам, а отдельный слой, **иллюстрирующий смысл**
  образом или действием.
- Крупный текст — редкий акцент, не пересказ сказанного.
- **Подпись ставится, только если добавляет то, чего в движении нет.** Имя, число,
  адрес, слово вроде «твой» — то, что картинка сама сказать не может. Слово,
  которое просто называет происходящее («залетает», «растёт», «выбор»), —
  дублирует субтитр и отнимает место у метафоры. Сцена, понятная без слов,
  остаётся без слов, и это законно.
- Исключение — первые секунды: там зритель смотрит без звука, и одно слово или
  число, за которое цепляется взгляд, окупается.
- Подходят и образные анимации (сеть строится, замок открывается, значение
  взлетает), и насыщенная инфографика (экран продукта, живые цифры, дашборд).
  Выбор по смыслу: про числа и данные — инфографика, про идею и процесс — образ.

**Главный принцип.** Анимация должна **быть** смыслом фразы, а не украшением рядом
с ней. Хорошо: «видят трое — забирает один» — трое подсвеченных силуэтов из толпы,
у одного галочка. Плохо: та же фраза и абстрактный график сбоку.

### Откуда берутся субтитры

Три положения дел, поле `subtitles.mode` в `config/project.json`:

| Режим | Что происходит | Что это значит для сцены |
|---|---|---|
| `own` (по умолчанию) | субтитры рисует сама система, слоем поверх графики | правило про текст остаётся ровно тем же: акцентные слова — якорь смысла, а не вторая строка субтитров |
| `external` | накладывает сторонний сервис после выгрузки | то же самое, плюс внизу оставлен запас вслепую: чужие субтитры неизвестного размера |
| `none` | субтитров нет вообще | только здесь ключевые фразы выводим сами и низ кадра свободен |

Свои субтитры **не отменяют ни одного правила этого раздела**. Соблазн большой:
раз текст рисуем мы, кажется логичным продублировать его крупно в кадре. Это
двойной пересказ одной и той же фразы, и он гарантированно съедает место, где
должна была быть метафора.

Слова для своих субтитров берутся из `work/words.clean.json` — той же расшифровки
чистой дорожки, по которой посчитаны длины блоков. Поэтому субтитры не могут
разъехаться со сценами: у них общий источник времени. Размер и разбивку на
страницы система подбирает сама, руками их никто не настраивает.

Один выбор всё же есть — `subtitles.chunk`: `page` (по умолчанию) держит на экране
фразу из нескольких слов и подсвечивает звучащее, `word` показывает по одному
слову без подсветки. Человек просит это словами — «пусть слова идут по одному»,
«убери подсветку», «сделай субтитры проще». Короткие слова в пословном режиме
никогда не стоят в кадре одни: «в шапке», «в один клик» едут одним блоком, это
правило ядра. Для сцены разницы нет: текст речи и так на экране, и правило про
подписи в обоих режимах одно.

Файлы `.srt` система не делает и делать не будет: субтитры либо внутри ролика,
либо их накладывает сервис у себя.

## 2. Жёсткие правила

0. **Безопасная зона.** Сверху и снизу кадра — мёртвые полосы: там интерфейс
   соцсети и субтитры. Весь контент оборачивается в `<Scene>`, который держит
   отступы сам. Флаг `debug` показывает границы. Ничего важного в нижнюю зону.
   **Врезка поверх камеры держит те же границы.** В `<Scene>` она не
   оборачивается — ей нужно точное место рядом с говорящим, — но числа берутся
   из конфигурации, а не ставятся на глаз: соцсеть показывает ролик чуть крупнее
   выгруженного, и то, что в файле стояло у самого края, в ленте окажется за
   краем.
   Нижняя граница считается системой и зависит от режима субтитров: своя полоса
   субтитров занимает место ровно по своей высоте, чужая — с запасом. Отдельной
   ручки «отступ снизу» нет намеренно, иначе две настройки разъедутся.
1. **Нет мёртвого кадра.** Движение на всю длину блока. Статика при звучащем
   голосе — сцена не принята. Как этого добиться — раздел 4. Блок, отданный
   камере, это правило выполняет сам: говорящий человек — живая картинка.
2. **Стиль только из стиль-пака.** Цвет, шрифт, скругление, эффект — из
   `style/tokens.ts`. Хардкод запрещён. Не хватает токена — спросить, не выдумывать.
3. **Анимируем образ и действие, а не буквы.** Подпись — только там, где добавляет
   то, чего в движении нет: имя, число, адрес. См. раздел 1. Прогонять
   метафора-тест.
4. **Одна мысль — одна сцена.** Не пихать два тезиса в кадр. Блоки бывают мелкими,
   это нормально и даже хорошо: смена кадра держит внимание.
5. **Синхрон с голосом.** Длина сцены равна длине блока речи; ударный момент
   анимации — на ударное слово.
6. **Метафора важнее экономии.** Готовую сцену брать только при точном совпадении
   смысла и всегда с вариацией — ритм, число, ракурс, акцент. Никогда один в один.
   Не легла честно — писать новую.
7. **Всё от номера кадра.** Движение через `useCurrentFrame()` и примитивы
   `core/anim.ts`, `core/motion.ts`. Реальное время, `setTimeout` и случайные числа
   без семени запрещены: кадры разойдутся при рендере.
8. **Имя композиции** — латиница, цифры, дефис, без подчёркиваний. Готовые файлы —
   тоже латиницей.
9. **Сцены перетекают, а не сменяются встык.** У каждого стыка есть движение:
   уходящий кадр уезжает, приходящий приезжает с той же стороны. Две одинаковые
   склейки подряд запрещены. Длину блоков переход не меняет. Раздел 4а.
10. **Движение слышно.** У каждого события на экране свой звук; просят роль, а не
    имя файла. Набор текста берётся куском, а не клавишей. Опаснее тишины здесь
    каша: озвучивается главное событие блока, а не каждое движение. Раздел 4б.

## 3. Процесс

### 3.1 Приём материала
Человек присылает что-то одно: тему, текст сценария, файл озвучки или видео с
камеры. Система заводит папку `projects/ГГГГ-ММ-ДД_имя/` сама и раскладывает
исходники по местам. Человека не просят создавать папки и переименовывать файлы.

Если пришла только тема — сначала сценарий (раздел 6), утверждение, потом дальше.

### 3.2 Чистка дорожки
Исходник — живая речь: паузы, запинки, «эээ», повторы, фальстарты. Всё это
вырезается до того, как считаются тайминги.

- Тишина длиннее порога режется, короткая — остаётся: дыхание нужно, зависание нет.
- По краям склейки оставляется немного тишины, иначе речь звучит обрубленной.
- На видео с камеры те же склейки применяются к картинке. Стыки видны — это цена
  честной чистки; смягчаются микро-наездом или перекрываются графикой.

Настройки агрессивности — в `config/project.json`, блок `cleanup`.

### 3.3 Тайминги
Чистая дорожка распознаётся, получаются слова с временными метками. По ним
размечаются смысловые блоки: границы — по смыслу и паузам. Дальше секунды
переводятся в кадры.

**Считается по чистой дорожке.** Тайминги с исходной — самая дорогая ошибка: весь
ролик разъедется с голосом, и заметно это станет только на просмотре.

### 3.4 Драматургия целого
Каркас по умолчанию: **зацепка → напряжение → доказательство → разворот → призыв**.
Не складывается в дугу — сказать об этом человеку, а не собирать как есть.

### 3.4а Кто в кадре: человек или графика
Этот выбор делается один раз, сразу после разметки блоков, и только когда прислано
видео с камеры. У каждого блока ровно два состояния, третьего нет:

- **камера** — показываются кадры присланного видео. Сцена для такого блока не
  пишется вообще;
- **графика** — человек уходит с экрана, его место занимает анимированная сцена
  на **непрозрачном** фоне стиля.

**Графика поверх говорящего лица не кладётся.** Это не «и то, и другое», а каша:
зритель не читает ни лицо, ни инфографику. Либо человек, либо кадр — встык.

**Единственное исключение — врезка.** Запрет направлен не на всякий пиксель
поверх видео, а на конкуренцию за внимание: полноценная сцена заставляет
выбирать, куда смотреть. Маленькое доказательство рядом с лицом так не работает —
оно идёт ВМЕСТЕ с речью: человек говорит «вот их цена», и рядом появляется цена.

Врезка — это скрин, число или короткая подпись, и живёт она по трём правилам:

- **лицо не закрывает никогда.** Разрешены только две полосы кадра — над зоной
  лица и под ней. Ядро считает их само (`core/format.ts`, `faceZone` и
  `insetBand`) и останавливает сборку, если врезка в них не влезла;
- **ставится только на камерном блоке** и только компонентом `<CameraInset>`.
  Врезка на графическом блоке — ошибка: там рисует сама сцена, и места весь кадр;
- **не заменяет сцену.** Не влезло в полосу — значит это уже не примечание к
  речи, а отдельная мысль, и ей нужен свой графический блок.

Полноценную сцену поверх лица система по-прежнему не соберёт: указать блоку и
`camera`, и `scene` разом `defineReel` не даст.

Три случая, и все три обслуживаются одним и тем же полем:

| Что прислали и зачем | Как размечается |
|---|---|
| видео, но нужен только голос | ни одного камерного блока: изображение не появится нигде |
| видео, и человека хотят видеть | часть блоков камерные, часть графические |
| только звук | камерных блоков не бывает, все блоки графические |

Что куда — решается по смыслу. Камере отдаётся то, что держится на человеке:
зацепка, личное суждение, обращение к зрителю, призыв в конце. Графике — то, что
на лице не читается: числа, перечисления, сравнения, схемы, доказательства
скринами. Ошибка в обе стороны видна сразу: сплошная камера — это разговорное
видео, а не ролик; сплошная графика при снятом человеке — зря снимали.

Это же и главная экономия работы. Отрисовать нужно только графические блоки:
половина камерных — половина сцен.

Технически: пометка живёт в `work/blocks.json`, поле `camera`. Каркас по ней
создаёт файлы сцен только для графических блоков и проставляет в `reel.tsx` либо
`camera: true`, либо `scene`. Указать оба или ни одного `defineReel` не даст.
Субтитры от этого не зависят: они идут поверх всего ролика одинаково.

### 3.5 Сцены
Под каждый графический блок — своя анимация ровно на его длину. Метафора момента, затем образ
или инфографика, затем движение на всю длину блока. Готовую сцену — только при
точном совпадении и с вариацией. Метафора-тест обязателен.

Механики под повторяющиеся типы фраз — перечисление, сравнение, рост, поток,
выбор, наполнение, интерфейс в работе — собраны в `docs/SCENES.md`. Там же
анатомия насыщенного кадра: герой, свита, воздух.

### 3.6 Проверка каждого блока
Длина совпадает с блоком речи. Нет статики. Метафора читается без текста. Контент
в безопасной зоне. Стиль только из токенов. Идиома стиля выдержана.

### 3.7 Сборка и рендер
Ролик описывается через `defineReel` в `projects/<проект>/reel.tsx`: источник
звука, список блоков, длительности. `defineReel` сам проверит, что сумма блоков
совпадает с длиной дорожки, и не даст собрать разъехавшийся ролик.

Свои субтитры подключаются здесь же и сами: каркас кладёт в папку проекта
`captions.json` — копию слов чистой дорожки, — а сборка рисует их слоем поверх
графики. Отдельного шага в конвейере у субтитров нет.

Порядок слоёв в кадре снизу вверх: фон стиля → живой слой → видео с камеры →
подложка графических блоков → сцены → субтитры → аватар.

Видео играет непрерывно от начала до конца — иначе порвётся звук, который из него
же и берётся. Видно его только в камерных блоках: в графических поверх него
ложится непрозрачная подложка стиля, и сцена рисуется уже на ней. Врезка
камерного блока идёт поверх видео, но вне зоны лица — см. 3.4а.

В звуке два слоя: голос и фоновая музыка. Музыка по умолчанию выключена;
включённая — берётся из банка `public/music/`, громкость и плавные вход-выход
считает ядро (`core/music.ts`). Конкретному ролику музыку можно сменить или
снять полем `music` у источника.

**Порядок работы с громкостью — часть канона, а не деталь настройки.** Сначала
голос приводится к стандартному уровню (это делает чистка дорожки, до всякой
музыки), и только потом под уже нормальный голос кладётся музыка — тише его на
принятую величину. Обратный порядок ломает звук: если поднимать громкость
готового ролика, вместе с голосом поднимется и музыка, соотношение останется
прежним, и на тихой записи музыка так и будет спорить с речью.

По той же причине треки в банке приведены к одной громкости при добавлении:
иначе один и тот же множитель давал бы разный результат на разных треках.

Сводить дорожку руками и «делать погромче» не нужно нигде: тихий исходник
перестал означать тихий ролик.

## 4. Как не получить мёртвый кадр

Запрещено: анимация отыграла за секунду, дальше висит картинка под звучащий голос.

Три способа заполнить всю длину блока:

1. **Растянутое действие** — основное движение разворачивается медленно, ровно на
   длину блока.
2. **Живое послесвечение** (чаще всего) — действие отыграло, объект продолжает
   жить: свечение дышит, точки мерцают, сигнал бежит, курсор пульсирует.
3. **Цепочка микро-событий** — несколько мелких действий подряд до конца блока.

Инструменты уже есть, изобретать не нужно:

| Файл | Что даёт |
|---|---|
| `core/motion.ts` | `breathe` дыхание, `drift` плавание, `orbit` вращение, `travel` бегущий сигнал, `sweep` скан, `flicker` мерцание, `ascentPoint` кривая взлёта |
| `core/anim.ts` | `enter` появление, `counter` набор числа, `grow` рост, `stepped` ступенчатость |
| `core/timing.ts` | единый ритм: длительности, кривые, дыхание, кроссфейд |
| `style/Ambient.tsx` | всегда-живой фоновый слой под каждой сценой |

Живой фон — страховка, а не замена работы. Сцена обязана двигаться сама.

**Со своими субтитрами автоматика становится слепой.** Подсветка слова меняет
картинку каждый кадр, и `npm run check` больше не видит застывшую под субтитрами
сцену — он честно об этом предупреждает. Значит проверка мёртвого кадра целиком
на человеке: пролистать ролик глазами.

**Замирание считается по числам сцены, и считается ДО первого рендера.** Кадры
движений в сцене уже написаны — значит и провал в них виден без сборки. Два
условия, оба обязательные:

- последнее движение блока кончается не раньше, чем за пять кадров до его
  конца;
- между соседними движениями нет промежутка длиннее двадцати кадров.

Не сошлось — правится сцена, а не запускается рендер.

**Мелкое движение за движение не считается.** Предмет меньше примерно одной
пятидесятой кадра — полоска, галочка, стрелка, знак — картинку не держит.
Длину блока закрывает предмет-герой.

## 4а. Склейки между сценами

Без склеек ролик читается сменой слайдов: кадр моргнул, и на его месте другой.
Глаз такой стык не переносит, а регистрирует как обрыв — и вместе с обрывом
теряется мысль, которая шла через два блока.

**Склейка — это одно продолженное движение, а не две анимации по краям стыка.**
Уходящий кадр уезжает, и приходящий приезжает С ТОЙ ЖЕ СТОРОНЫ, как будто оба
лежат на одной ленте и ленту протянули. Разъехавшиеся половины дают два толчка
вместо одного переноса — это самая частая ошибка, и на глаз она читается сразу,
даже если человек не может объяснить, что не так.

Поэтому склейка описывается одним вектором: откуда приходит новый кадр. Куда
уезжает старый, система считает из него же, и разойтись они не могут.

### Как ставится

Пометкой у блока — чем этот блок ПРИХОДИТ на смену предыдущему:

```ts
{ id: 'cena-3', text: '…', frames: 74, scene: Cena3, transition: 'push-up' }
```

Общая склейка ролика задаётся один раз, у блока переопределяется:

```ts
defineReel({ id: '…', transition: 'auto', blocks: [ … ] })
```

`'auto'` — по умолчанию. Система ведёт очередь сама: разную для разных роликов,
но всегда одну и ту же для одного, и без двух одинаковых подряд. Этого хватает
в большинстве случаев; руками склейка ставится там, где стык что-то значит.

### Что есть в наборе

Список открыт. Свою склейку регистрируют в `core/transitions.tsx` через
`registerTransition`, и дальше она называется по имени наравне со встроенными.

| Имя | Что происходит |
|---|---|
| `cut` | встык, без движения |
| `push-left`, `push-right`, `push-up`, `push-down` | кадр переносится в сторону |
| `sheet` | новый лист наезжает снизу поверх старого |
| `lift` | старый лист поднимают, под ним уже лежит новый |
| `slide-in` | короткий въезд сбоку |
| `zoom-in`, `zoom-out` | наплыв и отъезд |
| `through` | проход насквозь: старый пролетает мимо, новый выходит из глубины |
| `dissolve` | растворение без движения |
| `blur-through` | кадр расфокусируется и собирается заново |
| `tilt` | кадр заваливается и уходит вбок |
| `iris` | раскрытие из точки |
| `expand` | раскрытие из горизонтальной щели |
| `pinch` | схлопывание в точку |
| `collapse` | схлопывание в щель |

### Три свойства механизма

1. **Длина блока не меняется.** Переход живёт внутри отведённых блоку кадров:
   приход съедает первые, уход — последние. Синхрон с голосом цел, потому что ни
   один блок не стал длиннее.
2. **Сцена о переходе не знает.** Движение накладывается снаружи, обёрткой.
   Иначе каждая сцена начала бы уметь склеиваться, и правка механизма означала бы
   правку всех сцен разом.
3. **Врезка поверх камеры в склейку не входит.** Её место в кадре задано числами
   из настройки, и сдвиг на несколько кадров вынес бы её за безопасную границу.
   Безопасная зона важнее украшения стыка.

### Жёсткое

**Две одинаковые подряд не ставятся никогда.** Повторённый переход глаз выучивает
с первого раза, и стык снова читается сменой слайда. Сборка на этом
останавливается.

**Встык — не отсутствие склейки, а выбор.** `cut` ставится там, где предмет
продолжается из кадра в кадр и стыка не должно быть видно: одно действие через
несколько блоков идёт встык, иначе предмет пропадёт и появится заново. Только на
`cut` запрет повтора не распространяется — тянущееся действие может занимать
подряд сколько угодно блоков.

**Первый блок ниоткуда не приходит.** У него склейки нет, и звука шва тоже.

## 4б. Звук движения

Третий звуковой слой рядом с голосом и музыкой. Каждое событие на экране
получает свой звук: набор щёлкает, карточка приезжает со стуком, переключатель
переключается, шов шелестит.

**Зачем.** Глаз видит движение, ухо его не подтверждает — и ролик читается
макетом: вроде всё шевелится, а не происходит ничего. Это тот случай, когда
техническая мелочь решает, выглядит работа готовой или черновой.

### Как пишется попадание

У блока, кадрами от начала блока — как считает движение сама сцена. Сдвинулся
блок при перемонтаже, звук уехал вместе с ним.

```ts
{
  id: 'sborka', text: '…', frames: 92, scene: Sborka,
  sfx: [
    { at: 6, role: 'click' },
    { at: 12, role: 'typing', lasts: 40 },
    { at: 58, role: 'thud', align: 'peak' },
  ],
}
```

| Поле | Смысл |
|---|---|
| `at` | кадр внутри блока, ноль — первый |
| `role` | что произошло |
| `times`, `step` | повторить N раз через `step` кадров (по умолчанию 3) |
| `gain` | поправка громкости этого попадания |
| `variant` | конкретный вариант роли; обычно не указывается |
| `align` | `'start'` (по умолчанию) или `'peak'` |
| `lasts` | длина события на экране в кадрах, для `typing` и `scroll` |

**Кадры берутся из тех же констант, по которым живёт движение в сцене.** На глаз
нельзя: ухо ловит расхождение в один кадр там, где глаз не ловит и в три.

### Словарь ролей

Просят РОЛЬ — смысл события, а не имя файла. Сцена просит «щелчок», а какой
именно щелчок сегодня в банке, её не касается: поэтому смена банка не
переписывает ни одной сцены.

| Роль | Когда |
|---|---|
| `typing` | набор текста ЦЕЛИКОМ, одним звуком на весь кусок |
| `type` | одно нажатие: тап, Enter, один символ |
| `tick` | шаг счётчика, галочка по списку |
| `scroll` | непрерывная прокрутка |
| `select` | выбор, наведение, стало активным |
| `enter` | элемент появился в кадре |
| `swipe` | сдвиг на шаг |
| `open` / `close` | окно раскрылось / закрылось |
| `snap` | предмет встал на место |
| `drop` | предмет опустился сверху |
| `toggle` | переключатель |
| `check` | галочка поставлена |
| `click` | нажатие |
| `notify` | уведомление прилетело |
| `error` | ошибка |
| `whoosh` | шов между сценами |
| `intro` | затяжной вуш под целый блок, пик к стыку |
| `rise` | нарастание, только перед `thud` или `success` |
| `success` | готово |
| `thud` | тяжёлая посадка, не чаще раза на ролик |

Что лежит в банке под каждой ролью — `npm run sfx`.

### `typing` против `type`

Разные роли, и путать их нельзя. Повтор одной клавиши через равный шаг даёт
пулемёт: у живого набора интервалы неровные — 52, 36, 88, 194 миллисекунды, — и
слышно не тембр, а ритм. Ритм чередованием вариантов не чинится.

Поэтому набор текста берётся **куском**: одно попадание `typing` с `lasts` на всю
длину набора. `type` — только для одиночного нажатия.

### Длинный звук ставится пиком, а не началом

`align: 'peak'` двигает старт назад ровно на пик файла, чтобы на указанный кадр
пришёлся самый громкий момент звука. У разгона пик в конце, у затяжного вуша в
середине, у колокола через треть секунды: поставленные началом, они звучат мимо.

Считать сдвиг руками нельзя — длина вариантов роли разная, и арифметика под один
файл разъедется на следующем чередовании. Звук при этом свободно уезжает за
начало блока: **разгон живёт в предыдущей сцене, а разрешается в этой, и это
норма**, а не ошибка разметки.

### Какой файл прозвучит

1. Назван `variant` — берётся он.
2. Указан `lasts` — вариант, ближайший по длине. Рулон на четыре секунды под
   односекундную печать звучит как чужой звук поверх кадра. Если подходящий всё
   же длиннее, хвост уводится плавно: оборванный на полуударе набор слышен сразу.
3. Иначе очередь по роли, с чередованием: **один файл не звучит дважды подряд**.
   Повторённый один в один звук ухо выучивает мгновенно и дальше читает как
   заедание, а не как событие. Нужно подчеркнуть однотипность повторений — на это
   и есть `variant`.

### Прореживать надо руками

**Опаснее тишины здесь каша.** Двадцать щелчков в секунду сливаются в шум, из
которого не читается ни один, и ролик от этого звучит хуже, чем если бы молчал.

Система снимает лишнее сама, по всему ролику разом: всё, что легло вплотную к
шву; всё, что идёт слишком часто для своей роли; всё, что не пролезло в окно из
трёх кадров; всё сверх десяти попаданий в секунду. Но **снятое попадание — это
ненайденное движение, а не решённая задача**: автоматика убирает кашу, а не
находит смысл.

Правила расстановки:

- озвучивается **главное событие блока**, а не каждое движение;
- два события ближе шести кадров дают одно попадание;
- на самом плотном месте — три-четыре в секунду вместе со швом;
- если из восьми попаданий прозвучит меньше половины, система об этом скажет:
  значит они расставлены наугад.

### Швы озвучиваются сами

Единственное место, где звук ставится без участия автора. Переход уже описан у
блока, второй список означал бы однажды их разойтись. Роль берётся по ХАРАКТЕРУ
склейки, а не по её имени — поэтому своя склейка зазвучит сама:

```
кадр переносится, наплывает, растворяется → whoosh
кадр раскрывается из точки или щели       → open
кадр схлопывается в точку или щель        → close
встык                                     → молчит
```

Встык молчит намеренно: там стыка не должно быть слышно ровно так же, как не
должно быть видно. У блока можно поставить `seam: 'роль'` или `seam: false`, весь
механизм выключается настройкой `sfx.seams`. Руками швы не трогают.

### Осознанная пауза

`sfx: false` у блока — блок звучит одним голосом. Это законный приём: тишина
перед ударом делает удар. Но **снимать звук совсем нельзя** — молчащее движение
читается макетом.

Отдельному ролику звук снимается целиком тем же полем в его описании.

### Громкость

`sfx.volume` в `config/project.json`, по умолчанию `1.0`. Число не на глаз: голос
идёт около −12 LUFS по мгновенному окну, банк выровнен на −26 по тому же — при
единице самый громкий звук банка на четырнадцать децибел тише голоса. Ниже `0.5`
звуки перестают читаться под речью, выше `1.2` начинают с ней спорить. Трогать
только после того, как ролик послушали.

### Свои звуки

```
npm run sfx                                      что есть в банке
npm run sfx -- --add "<файл или ссылка>" --role click
npm run sfx -- --remove click-3.wav
```

Система сама скачает, переведёт в общий формат, срежет тишину по краям, выровняет
громкость, найдёт пик и допишет строку в банк. Исходное имя может быть любым — с
пробелами, кириллицей, скобками; наружу оно не попадает.

**Пустая роль — брак**: сцена попросит её и получит тишину. `npm run sfx`
помечает такие роли красным.

## 5. Текст в кадре

Полезная ширина — ширина кадра минус боковые поля. Обрезанное слово у края —
самый заметный вид брака.

Заголовки пишутся через `FitText` из `core/text.tsx`: он измеряет строку тем же
движком, который её нарисует, и раскладывает по строкам сам. Ручной подбор кегля
на глаз не нужен и вреден.

Порядок при нехватке места: сначала разбить по словам на строки, и только если
одно слово шире полосы — уменьшать кегль. Переносить внутри слова дефисом нельзя.

По высоте контент тоже обязан помещаться в рабочую зону: ужимать отступы, а не
надеяться на центрирование.

## 5а. Реальные скрины

Кроме нарисованной графики в ролик можно ставить настоящие экраны: интерфейс
продукта, страницу с ценой, счётчик, чужой сайт.

**Скрин — доказательство, а не иллюстрация.** Он уместен ровно там, где сцена
утверждает факт, в котором зритель может усомниться: конкретная цифра, чужой
интерфейс, цена, дата, чей-то результат. Идеи, процессы, выгоды и метафоры
остаются графикой. Метафора-тест скрин не проходит по определению — он не
движение, он свидетельство.

Правила, проверенные на практике:

- **Три-четыре скрина на сорокасекундный ролик, не больше.** Выше этого ролик
  перестаёт быть вашим по стилю и превращается в обзор-нарезку.
- **Точечные врезки** на полторы-две секунды под ударное слово.
- **В зацепке скрина нет.** Там нужен образ, а не документ. Максимум — вспышка
  фрагмента на доли секунды.
- **Неподвижный снимок запрещён в любом размере.** Картинка обязана жить: наезд,
  проход, дрейф — что-то из этого идёт всю длину блока.
- **Оправа берётся в пропорциях самого снимка, а не квадратом.** Широкая страница
  в квадратной оправе режется по краям, а вместе с краями пропадают приметы, по
  которым её узнают. Пропорции по умолчанию — окна съёмки из конфигурации
  (`shots.viewport`); для чужого файла с других пропорций число указывается
  прямо, поле `aspect`.
- **Наезд — там, где доказательство в мелкой цифре.** «12 825» в общем плане на
  вертикали превращается в серую крошку, и без наезда снимок ничего не
  доказывает.
- **Наезда не нужно, когда доказательство — сама страница.** «Это действительно
  их сайт» читается по шапке, адресу и общему виду; наезд съедает ровно эти
  приметы. Тогда снимок показывается целиком, а жизнь ему даёт дрейф.
- **Длинную страницу читают проходом** — поле `pan`: взгляд едет от одной точки к
  другой, сверху вниз. Так снимается старый плохой выбор «показать целиком и не
  прочитать или взять крупно и потерять всё остальное»: сначала видно, что это за
  страница, потом камера подъезжает и идёт по ней.
- **Снимок всегда через `ScreenPlate`** (`core/ScreenPlate.tsx`). Он берёт оправу
  из стиль-пака, держит пропорции, ведёт наезд или проход, добавляет дрейф и
  акцентное слово. Голый `Img` в сцене — это чужеродная неподвижная вставка, то
  есть брак.
- **Логотипы лучше не снимать,** а брать официальные векторные файлы из пресс-китов:
  они масштабируются без потерь и красятся в цвета стиля.
- Снимки делаются под конкретный ролик и живут в его папке. Общей библиотеки
  скринов нет и заводить её не нужно.

Съёмка идёт **между сценарием и сценами**. Раньше — ещё неизвестно, что сцена
должна доказывать; позже — сцена уже написана под картинку, которой может не
оказаться. На этом стыке отказ дешёвый: не снялось — сцена переписывается на
графику, потерь нет.

Что снимать, определяется на этапе сценария: проверяя факты и цифры, адреса
сразу складываются в список съёмки `projects/<проект>/shots.json`.

**Съёмка чужих сайтов выключена по умолчанию.** Свои снимки человек добавляет
всегда; хождение по сайтам — осознанное решение владельца, и включает его он сам.

## 5б. Имена вместо заглушек

Внутри окон, карточек и списков долго рисовались серые полоски вместо текста.
Приём верный, но применялся сплошь — и к середине ролика сцены пустели:
нарисовано красиво, а что именно происходит, зритель достроить не может.

**Если у вещи в кадре есть имя, оно пишется.** Файл называется `App.tsx`, модель —
Gemini, скилл — `code-review`, запрос звучит «собери рилс из этой озвучки», кнопка
говорит «собрать». Имя — это то, чего в движении нет, поэтому оно и не спорит с
правилом про редкие подписи из раздела 1: подпись называет смысл кадра, а имя
называет предмет внутри него.

**Полоски остаются там, где текст и есть масса,** которую читать не надо: абзацы,
код в фоне, длинное сообщение «слишком много букв», лента чужих сообщений. Там
серая полоска честнее текста — она сразу говорит «это просто много текста».

Имена подбираются правдоподобными и из мира темы. Ролик про сборку роликов —
`reel.tsx`, `words.clean.json`, «собрать». Ролик про аналитику — названия метрик и
отчётов. Выдуманное «Название 1» или `foo.js` в кадре читается как недоделка.

Как это выглядит в конкретном стиле — `style/IDIOM.md`.

## 6. Сценарий, если пришла только тема

Базовый модуль, один каркас — тот же, что в 3.4. Задача — не изобрести жанр, а не
дать человеку потеряться.

1. Уточнить: для кого ролик, какое действие ждём от зрителя, желаемая длина.
2. Написать текст под хронометраж: примерно 2.5 слова в секунду живой речи.
3. Показать целиком, дождаться утверждения. Не начинать производство до этого.
4. Дальше текст идёт либо в генерацию голоса, либо человеку на запись.

## 7. Технические грабли

Решены практикой, повторять не нужно.

- TypeScript 5.x. На 7.x сборщик падает.
- Браузер для рендера скачивается сам при первом запуске. Если домен недоступен —
  указать путь к своему Chrome через `--browser-executable`.
- Шрифты грузятся через загрузчик стиля, а задержка рендера объявляется внутри
  состояния компонента, не на верхнем уровне модуля. Иначе первый кадр уходит с
  неготовым шрифтом.
- Подписка кириллицы у шрифта обязательна, иначе русский текст молча уезжает на
  запасное семейство и вся выверка кеглей теряет смысл.
- Звук и видео лежат в `public/` и подключаются через `staticFile`.
- Порядок объявлений в токенах: не использовать значение до того, как оно
  определено.
- Готовые файлы — латиницей. Кодек H.264, профиль high, `yuv420p`, `faststart`,
  звук AAC: так ролик корректно принимают все площадки.

## 8. Команды

Полный порядок шагов с пояснениями — в `docs/PIPELINE.md`. Коротко:

| Команда | Что делает |
|---|---|
| `npm run install-deps` | ставит ffmpeg, whisper и модель распознавания |
| `npm run doctor` | проверка окружения: чего не хватает и как поставить |
| `npm run intake` | приём материала, создание папки проекта |
| `npm run transcribe` | речь в слова с временными метками |
| `npm run cleanup` | вырезка пауз, запинок, повторов |
| `npm run blocks` | разметка на смысловые блоки |
| `npm run scaffold` | каркас: файлы сцен, описание ролика, реестр |
| `npm run studio` | студия предпросмотра: листать кадры, смотреть сцены |
| `npm run render` | собрать готовый mp4 и проверить его |
| `npm run music` | банк фоновой музыки: показать, добавить своё |
| `npm run sfx` | банк звуков движения по ролям; `--add` кладёт свой звук. Раздел 4б |

Рендер идёт на процессоре локальной машины. На слабой — дольше, это нормально.
