# Конвейер: от присланного файла до готового mp4

Порядок шагов и что каждый делает. Человеку эти команды знать не нужно — он
просто присылает материал и говорит, что хочет; шаги выполняет система.

## Порядок

```
установка → проверка → настройка → приём → расшифровка → чистка →
блоки → каркас → сцены → рендер → проверка результата
```

Первые три шага делаются один раз на машине. Остальные — на каждый ролик.

## Один раз

| Шаг | Команда | Что происходит |
|---|---|---|
| Установка | «запускай установку» → `npm run install-deps -- --yes` | порядок — в своде `AGENTS.md`, раздел «Установка». Ставятся библиотеки, `.env`, ссылки скиллов, ffmpeg, whisper и модель распознавания. Ничего не делается молча; пароль человек вводит сам в системном окне |
| Проверка | `npm run doctor` | что на месте, чего не хватает и как это поставить |
| Настройка | «настрой фабрику» | формат кадра, озвучка, аватар, стиль |

## На каждый ролик

| Шаг | Команда | Что происходит |
|---|---|---|
| Приём | `npm run intake -- --name "имя" файл` | заводится папка проекта, исходники раскладываются, определяется что пришло |
| Озвучка | `node scripts/tts.mjs --project ID --text-file файл` | только если подключён ElevenLabs: текст превращается в речь **вместе с метками времени** |
| Расшифровка | `npm run transcribe -- --project ID` | локально, речь превращается в слова с точным временем |
| Чистка | `npm run cleanup -- --project ID` | вырезаются затянутые паузы, паразиты и повторы; голос проходит обработку (гул, шип, свистящие, ровный уровень) и выводится на стандартную громкость; слова пересчитываются под новую дорожку |
| Блоки | `npm run blocks -- --project ID` | речь режется на смысловые куски, считаются длительности в кадрах |
| Кто в кадре | — | только для видео с камеры: в `work/blocks.json` помечается, где остаётся говорящий человек, а где его сменяет графика. Подробно — `docs/METHOD.md`, 3.4а |
| Каркас | `npm run scaffold -- --project ID` | создаются файлы сцен — **только для графических блоков**, — описание ролика, запись в реестре; сюда же кладутся слова для субтитров |
| Сцены | — | человеческая часть: метафора под каждый графический блок вместо заглушки |
| Склейки | — | там же, вместе со сценами: у блока проставляется, чем он приходит на смену предыдущему. Не проставили — система ведёт очередь сама и двух одинаковых подряд не ставит. Подробно — `docs/METHOD.md`, 4а |
| Звук движения | — | там же, вместе со сценой: у блока проставляются попадания `sfx` — по тем же кадрам, по которым живёт движение. **Отдельного шага нет намеренно**: звук ставит тот, кто написал движение, иначе он не попадёт в кадр. Швы озвучиваются сами. Подробно — `docs/METHOD.md`, 4б |
| Рендер | `npm run render -- --project ID` | собирается mp4, кладётся в общую папку готовых роликов, сразу прогоняются проверки |

Идентификатор проекта — имя его папки в `projects/`, вида `2026-08-09-analitika`.

Два шага необязательные и включаются ключом в `.env`:

| Шаг | Команда | Когда |
|---|---|---|
| Озвучка | `node scripts/tts.mjs --project ID --text-file файл` | текст есть, голоса нет. Распознавание после этого не нужно: метки приходят от самого синтезатора и они точнее |
| Аватар | `node scripts/avatar.mjs --project ID` | нужна говорящая голова. Делается по чистой дорожке, ложится слоем поверх сцен |

## Где в конвейере субтитры

Отдельного шага у субтитров нет, и это не упущение: всё нужное появляется на уже
существующих шагах.

| Шаг | Что происходит с субтитрами |
|---|---|
| Чистка | появляется `work/words.clean.json` — слова с временем ЧИСТОЙ дорожки. Это единственный источник субтитров |
| Каркас | те же слова копируются в `projects/ID/captions.json` и подключаются к описанию ролика |
| Рендер | слой субтитров рисуется поверх графики сцен, разбивка на страницы считается на лету |

Файл кладётся всегда, даже когда субтитры сейчас внешние: тогда переключить режим
— это одна строчка в конфиге, а не пересборка проекта.

Что настраивается — блок `subtitles` в `config/project.json`, смысл полей в
`config/schema.md`. Размер страницы человек не настраивает: система считает его по
темпу речи и по ширине кадра. Настраивается только вид разбивки, поле `chunk`:
`page` — фраза с подсветкой звучащего слова, `word` — по одному слову без
подсветки. Короткие слова в пословном режиме склеиваются с соседом ядром, отдельно
это не настраивается.

Экспорта `.srt` в системе нет.

Скрины реальных экранов — отдельная, тоже необязательная ветка:

| Что | Команда | Доступность |
|---|---|---|
| Свои снимки | `npm run shots -- --project ID --import файл1 файл2` | всегда |
| Съёмка сайтов | `npm run shots -- --project ID --capture` | только если включено `shots.web` |
| Пересъёмка одного | `npm run shots -- --project ID --capture --only имя` | там же |
| Найти нужный блок страницы | `npm run probe -- https://example.com` | там же |

Список съёмки — `projects/ID/shots.json`:

```json
{
  "shots": [
    { "name": "pricing", "url": "https://example.com/pricing" },
    { "name": "stars", "url": "https://github.com/org", "area": "#org-repositories" },
    { "name": "long", "url": "https://example.com", "fullPage": true }
  ]
}
```

Без `area` и `fullPage` снимается первый экран. Снимки ложатся в
`projects/<проект>/work/public/shots/`, отчёт — в `work/shots-report.json`; пересъёмка одного
источника не затирает данные по остальным.

В кадре снимок ставится только через `ScreenPlate` — он даёт оправу из стиля в
пропорциях самого снимка, наезд или проход по странице (`pan`) и акцентное слово.

Выбор голоса и аватара:

```
node scripts/tts.mjs --voices
node scripts/tts.mjs --demo --text "Короткая фраза"
node scripts/avatar.mjs --avatars
```

## Куда попадают готовые ролики

Готовый файл лежит в **одном месте** — в папке `OUT REELS` **рядом** с папкой
системы. Путь задаётся полем `render.outputDir` и считается от корня системы.
Рендер пишет во временный `work/render.mp4`, выравнивает в нём громкость и
переносит в `OUT REELS`; по этому файлу идут и проверки, и правки.

Папка `OUT REELS` создаётся сама при первом рендере.

Папку самого проекта человек тоже не создаёт — её заводит `intake.mjs` в момент,
когда материал прислан.

## Что лежит в папке проекта

| | |
|---|---|
| `source/` | как прислали. Не трогается никогда |
| `work/` | рабочее: слова, список склеек, разметка блоков |
| `work/public/` | то, что видит рендер: чистая дорожка, аватар, снимки |
| `scenes/` | сцены — по одной на графический блок. Для блоков, где говорит человек, файлов нет |
| `reel.tsx` | описание ролика: источник звука, блоки, длительности |
| `captions.json` | слова чистой дорожки для своих субтитров |
| `meta.json` | карточка проекта и текущий шаг |

Материалы проекта лежат в `projects/ID/work/public/` и попадают в `public` только
на время рендера: папка переезжает туда перед сборкой и возвращается после. Пути
внутри ролика при этом остаются вида `ID/…`. Готовый ролик — только в `OUT REELS`.

Промежуточные файлы не мусор: по `work/blocks.md` человек глазами проверяет
разбивку, по `work/edl.json` видно, что именно вырезано.

## Настройки чистки на один прогон

Когда человек говорит «почисти построже» или «оставь дыхание»:

```
npm run cleanup -- --project ID --min-silence 0.5    какая пауза считается затянутой
npm run cleanup -- --project ID --threshold -40      что считать тишиной
npm run cleanup -- --project ID --keep-pad 0.15      сколько тишины оставить на стыке
npm run cleanup -- --project ID --no-fillers         не трогать слова-паразиты
```

Постоянные значения живут в `config/project.json`, блок `cleanup`.

## Настройки разметки блоков

```
npm run blocks -- --project ID --max 4.5     предел длины блока
npm run blocks -- --project ID --min 0.8     ниже которого блоки не дробятся
npm run blocks -- --project ID --pause 0.2   какая пауза считается границей мысли
```

Разметка по паузам — черновик. Границы мыслей уточняются по смыслу: это работа
человека и системы, а не секундомера.

## Что проверяется автоматически

Останавливает работу:

- сумма длительностей блоков не совпала с длиной дорожки — картинка разъедется
  с голосом (`defineReel`, ещё до рендера);
- у блока не сказано, что на экране: нет ни сцены, ни пометки камеры — или
  указано и то, и другое сразу;
- блок помечен камерным, а видео у ролика нет;
- имя ролика не годится для композиции;
- готовый файл пуст или оборван.

Предупреждает, но решает человек:

- картинка замирает дольше 0.7 секунды под звучащий голос — с указанием блока;
- подозрительно короткие блоки.

Живой фоновый слой сам по себе проверку на замирание не проходит — и это
правильно: он страховка, а не замена сцене.
