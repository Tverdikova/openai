# Фабрика роликов — инструкция системе

Этот файл читается в начале каждого разговора. Он существует затем, чтобы правила
производства не пропускались: именно пропуски дают брак.

Общаться с человеком по-русски, просто, без технических подробностей, если он о них
не спросил. Он не программист и не обязан им становиться.

---

## Маршрутизатор: что делать в ответ на обращение

| Человек прислал или сказал | Что делать |
|---|---|
| «запускай установку» | установка по порядку ниже, от начала до конца |
| файл озвучки, видео с камеры, текст сценария или просто тему, «собери ролик» | сборка ролика: завести папку проекта, разложить исходники, уточнить недостающее — и вести ролик до готового mp4 |
| только тему, без текста, «напиши сценарий» | написать сценарий, показать на утверждение, и лишь потом производство |
| «поправь вот это в ролике» | правка последнего собранного ролика в этом же разговоре |
| музыкальный файл или ссылка на трек | `npm run music -- --add <файл или ссылка>`: система скачает, выровняет громкость и положит в банк |
| папка со звуками или отдельный звуковой эффект | разложить по ролям и добавить в банк: `npm run sfx -- --add <файл> --role <роль>` |
| «какие есть звуки» | `npm run sfx` |
| «убери звуки», «сделай тише щелчки» | `sfx.enabled` и `sfx.volume` в `config/project.json`. По умолчанию звук движения включён |
| «включи музыку», «убери музыку» | `music.enabled` в `config/project.json`. По умолчанию музыки нет |
| «настрой фабрику», «подключи озвучку», «подключи аватар» | мастер настройки |
| «поменяй стиль», «подключи мой дизайн-код» | подключить или обновить дизайн-код |
| «что-то не работает», «ошибка», «проверь, всё ли на месте» | `npm run doctor`, затем объяснить результат человеческими словами |

Всё управление — обычными словами. Команд человеку не показывать и не просить
их выполнять, даже когда их советует вывод скрипта: команды запускаешь ты сам, а
человеку говоришь, что происходит, и что от него нужно — словами.

Порядок при первом обращении на этой машине:

1. **Сначала техника.** Человек написал «запускай установку» или `npm run doctor`
   показывает нехватку — пройти установку по порядку ниже и довести её до конца.
   Не начинать производство на неготовой машине.
2. **Потом проверка.** Повторить `npm run doctor`, убедиться что всё на месте.
3. **Потом настройка — по желанию.** `"configured": false` — предложить одной
   фразой настройку и свой стиль. Человек отказался или сразу прислал материал —
   собирать на значениях по умолчанию, в базовом оформлении.
4. Затем производство.

### Установка

Установку ведёшь сам, от начала до конца. От человека нужны только два действия:
подтверждать твои команды и нажимать «Да» в системных окнах — на Windows это окно
разрешения на изменения, на Mac окно с паролем учётной записи. Пароль за человека
не вводить, команд для Терминала ему не давать, установочных файлов запускать не
просить.

1. **Node.js 20 или новее.** Проверить `node -v`. Нет или старее — поставить самому:
   - Windows: `winget install -e --id OpenJS.NodeJS.LTS --accept-source-agreements --accept-package-agreements`;
   - Mac с Homebrew: `brew install node`. Без Homebrew — официальный установщик:
     имя файла последней LTS-версии взять из `https://nodejs.org/dist/index.json`,
     скачать `https://nodejs.org/dist/v<версия>/node-v<версия>.pkg` и открыть
     командой `open`. Пароль человек вводит в системном окне.

   Свежий Node программа, в которой идёт работа, увидит только после перезапуска.
   Если `node -v` по-прежнему молчит — попросить человека перезапустить её и
   написать «продолжай установку».
2. **Всё остальное — одной командой:** `npm run install-deps -- --yes`. Она ставит
   библиотеки фабрики, делает `.env` из `.env.example`, восстанавливает ссылки
   скиллов, ставит ffmpeg, whisper и скачивает модель распознавания. На слабой
   машине добавить `--model small`. Команда остановилась — прочитать почему,
   устранить и запустить снова: она продолжает с места остановки. На Mac без
   Homebrew она сама откроет его установщик — человек подтверждает и вводит пароль
   в системном окне, после чего команда запускается снова.
3. **Windows: скиллы.** Скиллы лежат в `.agents/skills/`, а в `.claude/skills/` на
   месте каждого — ссылка на его папку. Из архива на Windows ссылки не
   восстанавливаются, их создаёт шаг 2 — соединением папок. Если это не удалось,
   создать вручную: удалить пустышку на месте ссылки и выполнить
   `cmd /c mklink /J .claude\skills\<имя> .agents\skills\<имя>` для каждого скилла.
   Прав администратора и режима разработчика соединение не требует.
4. **Codex: разрешения.** Только если работа идёт в Codex. Конвейер запускает
   десятки команд подряд, ходит в сеть и пишет готовый ролик за пределы папки
   фабрики. В `~/.codex/config.toml` (нет — создать):

   ```toml
   approval_policy = "on-request"
   sandbox_mode = "workspace-write"

   [sandbox_workspace_write]
   network_access = true
   writable_roots = ["ПАПКА_ГОТОВЫХ_РОЛИКОВ"]
   ```

   - `writable_roots` — полный путь, куда разворачивается `render.outputDir` из
     `config/project.json`. Путь там относительный и считается от папки фабрики;
     наугад не подставлять. Лежит внутри фабрики — строка не нужна. Пропустить
     сверку — рендер отработает целиком и упадёт на последнем шаге.
   - `network_access = true` — для установки, модели, музыки, озвучки и съёмки
     сайтов. Распознавание речи идёт локально.
   - `danger-full-access` не ставить, `workspace-write` достаточно.
   - `render.outputDir` не менять ради прав на запись: чинится разрешение, а не
     настройка.
   - В файле уже есть свои значения — чужие настройки не затирать молча: показать
     человеку, что меняется и что остаётся как было.
5. **Проверка.** `npm run doctor` — всё зелёное. Пункты «можно» про ключи и мастер
   настройки поломкой не считаются. Свежепоставленные программы не находятся —
   это тот же перезапуск, что в шаге 1.
6. **Новый разговор.** Попросить человека открыть новый разговор: скиллы
   подхватываются при его запуске. Менялись разрешения Codex или на Windows
   ставились программы — перезапустить программу целиком. В новом разговоре —
   предложить настройку или сразу прислать видео.

Шаги конвейера и их порядок — в `docs/PIPELINE.md`.

## Правки файлов

Правь только инструментом редактирования. `sed -i`, `python` с записью файла,
`cat > файл` и любая другая правка через командную строку запрещены — даже
точечная замена одной строки: файл записывается целиком и целиком возвращается
в память. Десяток таких правок обходится дороже, чем всё производство ролика.

## Один ролик — один разговор

Новый ролик начинается в новом разговоре. В старом остаётся весь предыдущий: он
занимает место, замедляет работу и подталкивает повторять уже использованные сцены,
что запрещено правилами.

Это ничего не теряет: всё состояние лежит в файлах — папка проекта, конфигурация,
стиль-пак, банк исходников. Новый разговор читает этот файл и продолжает с того же
места. Если человек начал второй ролик в том же разговоре — спокойно предложить
открыть новый.

В том же разговоре остаётся только одно: правки ролика, который только что собран.

## Перед сборкой или правкой ролика

Прочитать **`docs/METHOD.md` целиком** — там весь канон производства. Не начинать
писать сцены, пока он не прочитан. Правишь только внешний вид — всё равно свериться
с разделами про идиому и жёсткие правила.

Затем прочитать **`style/IDIOM.md`** — визуальный язык текущего стиля, и
**`style/tokens.ts`** — из чего этот стиль состоит.

Склейка и звук пишутся ВМЕСТЕ со сценой, а не после неё: кадры попаданий берутся
из тех же констант, по которым живёт движение, и задним числом их не восстановить.
Словарь ролей, правила прореживания и набор склеек — **`docs/METHOD.md`, разделы
4а и 4б**, состав банка — `npm run sfx`.

Когда дело дошло до самих сцен — **`docs/SCENES.md`**: библиотека механик под
повторяющиеся типы фраз и анатомия насыщенного кадра. Готовая механика берётся
только при совпадении метафоры и всегда с вариацией.

## Непререкаемое (полностью — в docs/METHOD.md)

1. **Нет мёртвого кадра.** Экран движется всю длину блока озвучки. Статика при
   звучащем голосе — брак.
2. **Синхрон.** Длина сцены равна длине её блока речи; ударный момент анимации
   попадает на ударное слово. Тайминги берутся из расшифровки **почищенной**
   дорожки, а не исходной.
3. **Анимируем смысл, а не буквы.** Субтитры — свои или чужие, это настройка. Текст речи и так на экране, и когда субтитры рисуем мы,
   правило не смягчается. Наш кадр иллюстрирует мысль образом или действием.
   Подпись в кадре ставится, только если добавляет то, чего в движении нет: имя,
   число, адрес, слово вроде «твой». Сцена, понятная без слов, остаётся без слов.
3а. **У вещей в кадре есть имена, и они пишутся.** Файл называется `App.tsx`,
   кнопка говорит «собрать». Серые полоски — только там, где текст и есть масса,
   которую читать не надо. Правило целиком — `docs/METHOD.md`, раздел 5б.
4. **Метафора-тест.** Уберите весь текст — мысль читается из одного движения? Нет —
   метафора не найдена, думать заново.
4а. **Человек или графика, но не вместе.** Прислано видео с камеры — каждый блок
   отдаётся либо говорящему человеку, либо анимации на непрозрачном фоне стиля.
   Графика поверх лица — брак. Разметка делается один раз после разбивки речи,
   правило целиком — `docs/METHOD.md`, раздел 3.4а.
4б. **Сцены перетекают, а не сменяются встык.** У каждого стыка есть движение:
   уходящий кадр уезжает, приходящий приезжает с той же стороны — это одно
   продолженное движение, а не две анимации по краям. Склейка ставится пометкой
   `transition` у блока; список склеек не закрыт, своя добавляется в реестр.
   **Две одинаковые подряд не ставятся никогда**: повторённый переход глаз
   выучивает с первого раза, и стык снова читается сменой слайда. Встык — не
   отсутствие склейки, а осознанный выбор там, где предмет продолжается из кадра
   в кадр. Длину блоков переход не меняет: синхрон с голосом цел.
4в. **Движение слышно.** У каждого события на экране свой звук: набор текста
   щёлкает, карточка приезжает со стуком, переключатель переключается, шов
   шелестит. Звук ставится пометкой `sfx` у блока, кадры считаются от начала
   блока и берутся из тех же констант, по которым живёт движение в сцене, — на
   глаз нельзя, ухо ловит расхождение в один кадр. Просят звук — просят **роль**
   (`click`, `enter`, `whoosh`), а не имя файла.
   **Набор текста берётся куском, а не клавишей**: роль `typing`, одно попадание
   на всю длину набора. Роль `type` — для одиночного нажатия.
   **Длинный звук ставится пиком, а не началом**: пометка `align: 'peak'`, сдвиг
   система считает сама. Разгон живёт в предыдущей сцене, а разрешается в
   следующей, и это норма.
   **Опаснее тишины здесь каша**: звук ставится только туда, где действительно
   что-то произошло. Лишнее система снимет сама, но снятое попадание — это
   ненайденное движение, а не решённая задача. Швы озвучиваются системой, руками
   их не трогать.
   **Прореживать список надо руками, автоматика кашу не ловит**: озвучивается
   главное событие блока, а не каждое движение; два события ближе шести кадров
   дают одно попадание; на плотном месте три-четыре в секунду со швом. Снимать
   звук совсем нельзя — молчащее движение читается макетом.
5. **Безопасная зона.** Весь контент — через `<Scene>`. Границы берутся из
   конфигурации, руками отступы не расставляются. Врезка поверх камеры в
   `<Scene>` не оборачивается, но держит те же границы и те же числа из
   конфигурации: соцсеть подрезает кадр при загрузке, и поставленное на глаз у
   края в ленте окажется за краем.
6. **Стиль только из стиль-пака.** Цвета, шрифты, скругления, эффекты — из
   `style/tokens.ts`. Хардкод стиля в сценах запрещён. Не хватает токена — не
   выдумывать, а спросить человека.
7. **Всё от номера кадра.** Движение считается через `useCurrentFrame()` и примитивы
   `core/anim.ts` и `core/motion.ts`. Никакого реального времени и случайных чисел
   без семени — иначе кадры разойдутся при рендере.
8. **Имя композиции** — латиница, цифры, дефис. Без подчёркиваний.
9. **Служебные пути — латиницей.** Кириллица и пробелы в путях ломают рендер на
   Windows. Русский — в интерфейсе и документации, не в именах файлов.

  решает `npm run doctor`.

Формулировать спокойно и по-деловому, без пафоса и без рекламы.

## Скрины реальных экранов

Отдельная функция, см. раздел про скрины в `docs/METHOD.md`.

Коротко: свои снимки человек может добавлять всегда. **Съёмка чужих сайтов
выключена по умолчанию.**

Просят найти или снять что-то в интернете при выключенной функции — не включать
молча и не отказывать глухо. Ответить по трём пунктам:

1. это отдельная функция, и сейчас она выключена — система не ходит по сайтам,
   пока владелец не разрешил;
2. почитать о ней — **мануал, раздел 2.5 «Скрины реальных экранов»** (тот же
   текст в `docs/GUIDE.md`): что она умеет, чего не умеет (страницы за паролем не
   снимаются) и чья ответственность за чужие материалы в кадре;
3. включить можно прямо сейчас — достаточно сказать «включи съёмку сайтов», и
   тогда в `config/project.json` ставится `shots.web: true`.

Получив явное согласие, включить и продолжить работу. Пока согласия нет —
предложить обойтись своими снимками или графикой, ролик от этого не встанет.

## Где что лежит

| Папка | Что там |
|---|---|
| `core/` | ядро: формат, безопасная зона, ритм, движение, замер текста, сборка. Клиент не трогает, и система тоже — правки ядра только по прямой просьбе |
| `style/` | стиль-пак: токены, фон, живой слой, шрифты, идиома. Меняется по просьбе «поменяй стиль» |
| `.agents/skills/` | скиллы: сборка ролика, сценарий, настройка, стиль. Один экземпляр на все программы |
| `.claude/skills/` | ссылки на папки из `.agents/skills/`, не копии. Правится только `.agents/skills/` |
| `projects/` | ролики. Папку проекта заводит система сама при приёме материала |
| `OUT REELS` (рядом с системой, снаружи) | готовые ролики для человека. Создаётся сама при первом рендере, путь — `render.outputDir` |
| `config/` | настройки, их пишет мастер |
| `scripts/` | конвейер: приём, расшифровка, чистка, тайминги, рендер, проверки |
| `docs/` | канон производства и справка |

`docs/GUIDE.md` — текстовая копия мануала, который человек получил при покупке, с
той же нумерацией разделов. Отправляя его читать, называй **раздел мануала**
(«раздел 2.5»), а не путь к файлу: у него на руках PDF, а не папка docs. Сам же
загляни в `GUIDE.md`, если спрашивают о возможностях системы, — ответ там есть.

## Рендер

Рендер идёт на процессоре локальной машины и занимает время — это нормально.
Команды описаны в `docs/METHOD.md`. В облачной среде без графики рендер не
поднимается: там можно только готовить код.

**Замирание считается до первого рендера, а не ищется после.** Проверка по числам
сцены, глазами её не поймать: раздел 4 в `docs/METHOD.md`. Гонять полный рендер
ради этого — по две минуты за попытку.
